# Win11Debloat 한국어판 사용 가이드

이 문서는 **WEBIS가 현지화한 비공식 Fork**의 설치·실행·설정·복구를 안내합니다. 프로그램의 원저작자는 [Raphire](https://github.com/Raphire)이며, 기능의 기준은 [Raphire/Win11Debloat](https://github.com/Raphire/Win11Debloat)입니다.

**현재 한국어판은 검증 중입니다.** 아래 설명은 소스의 동작을 확인한 사용 안내이며, 모든 Windows 환경에서 실행 검증을 마쳤다는 뜻은 아닙니다. 실제 검증 환경·결과·미검증 항목은 [STATUS.md](STATUS.md)를 확인하세요.

[README로 돌아가기](../../README.md) · [유지보수와 번역 정책](MAINTENANCE.ko-KR.md)

## 1. 실행 환경과 준비

| 항목 | 안내 |
|---|---|
| Windows | 원본이 대상으로 하는 Windows 10 / Windows 11. 옵션마다 최소·최대 빌드 제한이 있음 |
| PowerShell | Windows PowerShell 5.1(`powershell.exe`). PowerShell 7(`pwsh`) 제품 실행은 지원하지 않음 |
| 권한 | 관리자 권한 필요. 일반 권한 실행 시 승격 절차가 나타남 |
| GUI | Windows WPF 사용. 앱 선택 등 일부 대화상자도 WPF를 사용 |
| 네트워크 | ZIP을 받은 뒤 로컬로 실행할 수 있으나 WinGet 등 일부 기능은 환경·네트워크에 의존 |
| 복구 준비 | 중요한 파일 별도 백업, 테스트 VM이면 실행 전 스냅샷 확보 |

프로그램 실행 지원과 해당 Windows 버전의 보안 업데이트 지원은 별개입니다. 관리 중인 PC의 업데이트 정책을 유지하세요. 회사·기관의 정책으로 기능이 제한된 경우 먼저 관리 담당자에게 확인하세요.

처음 사용할 때는 모든 추천 항목을 한 번에 적용하지 말고, **앱 제거 없이 필요한 설정 한두 개부터** 확인하는 편이 변경 원인을 파악하기 쉽습니다. 중요한 문서를 저장하고 프로그램을 닫은 후 시작하세요.

## 2. 올바른 파일 다운로드

### 한국어판과 원본 구분

| 주소 | 무엇을 받는가 |
|---|---|
| [webiscorp/Win11Debloat-koKR/releases](https://github.com/webiscorp/Win11Debloat-koKR/releases) | WEBIS 한국어판 배포 목록 |
| [한국어판 master 소스 ZIP](https://github.com/webiscorp/Win11Debloat-koKR/archive/refs/heads/master.zip) | 한국어판 저장소의 개발 소스. 안정판 검증을 뜻하지 않음 |
| [Raphire/Win11Debloat/releases](https://github.com/Raphire/Win11Debloat/releases) | 원본 프로젝트의 배포 목록 |
| `https://debloat.raphi.re/` | 원본의 다운로드·실행 진입점. 한국어판 전용 설치 주소가 아님 |

한국어판 안정 Release가 없으면 안정판 파일도 아직 없습니다. 개발 소스는 별도 테스트 환경용으로만 사용하세요. 작업 브랜치의 변경은 `master`에 병합된 이후 해당 ZIP에 포함됩니다.

ZIP을 다운로드하고 **전체 파일을 압축 해제**합니다. `Run.bat`과 `Win11Debloat.ps1` 옆에 `Config`, `Scripts`, `Schemas`, `Regfiles`, `Assets` 폴더가 있어야 합니다. 폴더 일부가 없으면 같은 한국어판 버전의 파일을 다시 받으세요. 서로 다른 버전의 파일을 섞지 마세요.

### 무결성 확인

향후 Release에서 ZIP과 `SHA256SUMS`를 함께 제공하면, Windows PowerShell에서 ZIP의 SHA-256을 계산하여 **같은 Release의 같은 파일명 행**과 비교합니다.

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath .\Win11Debloat.zip
Get-Content -LiteralPath .\SHA256SUMS
```

파일명이 다르면 Release에 적힌 실제 ZIP 파일명을 사용합니다. 해시가 다르면 실행하지 말고 다시 다운로드한 뒤 확인하세요. 체크섬은 파일이 배포 기록과 같은지 확인하는 수단이며, 코드의 안전성이나 실사용 검증을 대신하지 않습니다. GitHub가 생성한 소스 ZIP에는 별도 체크섬 배포가 없을 수 있으므로 체크섬 검증이 완료되었다고 간주하지 않습니다.

한국어판의 `Scripts/Get.ps1`은 별도 다운로드·실행 진입점입니다. 처음 사용하는 경우 ZIP을 확인하고 로컬 실행하는 절차를 사용하세요. 검증되지 않은 원격 스크립트 즉시 실행 명령은 이 문서에서 제공하지 않습니다.

## 3. GUI 실행

### Run.bat으로 실행

1. 압축을 푼 폴더에서 `Run.bat`를 실행합니다.
2. Windows의 관리자 권한 요청(UAC)을 확인합니다.
3. 프로그램이 열리면 적용할 사용자를 확인합니다.
4. **사용자 지정 설정**에서 필요한 항목을 선택합니다.
5. **배포 설정**에서 앱 제거 범위·백업·복원 지점·파일 탐색기 재시작 옵션을 확인합니다.
6. **선택한 변경 사항 검토**에서 실제 적용 예정 목록을 확인합니다.
7. 의도한 항목만 선택되었으면 **변경 사항 적용**을 누릅니다.
8. 완료 화면에서 실패·취소·재시작 필요 안내를 확인합니다. 완료 문구만 보고 모든 작업이 성공했다고 판단하지 마세요.

### Windows PowerShell로 직접 실행

Windows PowerShell을 관리자 권한으로 열고 압축 해제한 폴더로 이동합니다. 다음은 폴더 위치가 `C:\Tools\Win11Debloat-koKR`인 예입니다.

```powershell
Set-Location -LiteralPath 'C:\Tools\Win11Debloat-koKR'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Win11Debloat.ps1 -Language ko-KR
```

`-ExecutionPolicy Bypass`는 새로 실행하는 프로세스에 적용합니다. 컴퓨터 전체의 실행 정책을 영구 변경하는 절차가 아닙니다. 조직의 보안 정책을 우회하기 위한 안내가 아니며, 정책 때문에 실행할 수 없다면 관리 담당자에게 문의하세요.

**Windows Terminal은 터미널 창이고 PowerShell은 그 안에서 실행하는 셸입니다.** Terminal을 사용하더라도 `pwsh` 대신 `powershell.exe`로 실행해야 합니다. 현재 진입 스크립트는 PowerShell 7에서 Appx·시스템 복원 관련 기능을 정상 수행할 수 없으므로 실행을 중단합니다.

## 4. 언어와 테마

언어 선택 우선순위는 **실행 시 `-Language` → 저장한 언어 → Windows 표시 언어**입니다. 저장 설정이 `Auto`이면 Windows 표시 언어를 따릅니다.

| 원하는 동작 | 방법 |
|---|---|
| 이번 실행을 한국어로 | `-Language ko-KR` |
| 이번 실행을 영어로 | `-Language en-US` |
| 이번 실행에서 시스템 언어 따르기 | `-Language Auto` |
| 다음 실행에도 원하는 언어 사용 | GUI 상단 설정에서 언어를 선택하고 저장 |
| 밝게·어둡게·자동 전환 | GUI 상단 설정에서 테마를 선택하고 저장 |

GUI에서 저장하면 언어와 테마가 갱신됩니다. 창을 닫기만 하면 저장되지 않습니다. 실행 매개변수로 언어를 지정하는 것과 GUI에서 저장하는 것은 구분됩니다. 한국어판이라고 해서 기존 영어 설정을 자동으로 덮어쓰지 않습니다.

한국어 언어 파일을 읽을 수 없으면 영어로 대체될 수 있습니다. 영어 파일까지 없거나 손상되었으면 정상 실행할 수 없습니다. 해당 한국어판 버전의 전체 파일을 다시 받아 복구하세요.

한국어가 깨지거나 잘리면 Windows 표시 배율·화면 해상도·테마·문제가 있는 화면과 문구를 함께 기록하세요. 자동 테스트만으로 실제 한글 입력, 모든 DPI 배율, 테마별 가독성이 검증되는 것은 아닙니다.

## 5. 주요 기능과 선택 기준

### 앱 제거

앱 이름·설명·앱 ID로 제거 대상을 확인합니다. **설치된 앱만 표시**와 검색을 이용하고, 제거할 앱에만 체크하세요. 추천 표시는 현재 사용자의 업무·게임·장치 환경을 검사한 결과가 아닙니다.

**적용 사용자**와 **앱 제거 대상**은 별도 설정입니다. 앱 제거 기본 범위는 모든 사용자이며, Appx 프로비저닝 제거까지 포함될 수 있습니다. 내 계정만 정리하려면 배포 설정에서 현재 사용자만으로 범위를 확인하세요. 특정 사용자·Sysprep·WinGet 앱은 처리 방식이 다르므로 테스트 후 배포하세요.

| 앱 종류 | 제거 전에 확인할 내용 |
|---|---|
| Microsoft Store | 앱 설치·업데이트와 재설치 경로가 어려워질 수 있음 |
| 현재 실행 중인 터미널 | Win11Debloat 세션이 종료될 수 있음 |
| Microsoft Edge | 원본 설명상 Windows Sandbox의 브라우저와 다른 앱에 영향 가능 |
| Xbox·Game Bar·게임 관련 구성 요소 | 로그인·게임 기능·녹화 등에 영향. 일부 장치의 성능 영향 경고도 확인 |
| 제조사 도구 | 배터리 충전·팬·입력 장치·장치 지원 기능을 사용하는지 확인 |
| 지원 중단 앱 | 대체 앱·사용 중인 데이터·재설치 가능 여부를 먼저 확인 |

앱을 삭제하기 전에 앱 내부 데이터의 별도 백업이 필요한지 확인하세요. Win11Debloat는 삭제한 앱 전체를 자동으로 재설치하는 도구가 아닙니다. 일부 WinGet 제거는 다음 로그인이나 재시작으로 미뤄질 수 있으며, 로그의 성공·실패·확인 불가·지연 안내를 구분해야 합니다.

### 개인 정보와 원격 분석

원격 분석(텔레메트리), 진단·활동 정보, 광고 ID, 추천 콘텐츠, 웹 검색 연동, 위치 등 각 옵션의 설명을 읽고 선택합니다. 위치·추적 관련 기능을 끄면 위치 기반 앱이나 내 장치 찾기에 영향을 줄 수 있습니다. 개별 옵션 적용만으로 모든 데이터 수집이 중단되거나 개인정보 보호가 보장되는 것은 아닙니다.

### 시작 메뉴·작업 표시줄·파일 탐색기

시작 메뉴의 고정된 앱과 추천 영역, 작업 표시줄 정렬·검색·위젯, 파일 확장명·숨김 항목·기본 시작 위치 등을 조정할 수 있습니다. 원본이 각 Windows 빌드에 대해 제공한 기능만 사용합니다. 시작 메뉴 고정 항목 변경은 앱 설치 자체와 다릅니다.

### AI·게임·시스템·선택적 기능

AI 관련 옵션은 Copilot·Recall 등 각각의 기능을 다룹니다. 특히 `DisableCopilot`은 레지스트리 설정 변경과 Copilot 앱 제거를 함께 수행합니다. 해당 옵션을 되돌리거나 레지스트리 백업을 복원해도 삭제된 앱의 재설치까지 보장하지는 않습니다. 전원·빠른 시작·Modern Standby·마우스·저장소 관련 옵션은 사용 방식과 장치에 맞게 선택합니다. Windows Sandbox·WSL처럼 재시작이나 Windows 기능 활성화가 필요한 옵션도 있습니다. 설명에 없는 성능 향상이나 모든 장치에서의 호환성을 가정하지 마세요.

### Windows 업데이트

업데이트 배포 시점, 로그인 상태에서의 자동 재시작, 배달 최적화, 장치 보조 앱 자동 설치 등의 옵션을 구분합니다. 이를 **모든 업데이트를 안전하게 끄는 기능**으로 해석하지 마세요. Windows 업데이트 후 일부 설정이나 앱이 다시 적용될 수 있으며, 새 빌드에서는 특정 옵션이 달라질 수 있습니다. 문제가 생기면 Windows 빌드와 적용 항목을 함께 확인합니다.

## 6. 설정 파일 가져오기·내보내기

설정 파일은 선택한 앱·시스템 조정·배포 옵션을 재사용하기 위한 JSON입니다. 내보내기와 가져오기에서 포함할 범주를 확인합니다.

- 내보낸 설정 파일은 **선택 목록**이며 기존 시스템 상태의 백업이 아닙니다.
- 다른 PC에 가져오기 전에 앱 목록·대상 사용자·제거 범위·Windows 빌드를 다시 확인하세요.
- 기존 설정의 영어 키, 기능 ID와 앱 ID는 번역하거나 직접 바꾸지 마세요.
- `LastUsedSettings.json`은 마지막 선택 정보이며 실제 적용 성공 여부나 복원 가능성을 증명하지 않습니다.

언어와 테마는 `Preferences.json`에 별도로 저장됩니다. 기존 사용자 설정·백업 형식을 유지하는 것이 한국어판의 원칙입니다.

## 7. 명령행 사용

아래 명령은 **관리자 권한 Windows PowerShell**에서 압축 해제한 폴더를 기준으로 실행합니다. 매개변수 이름은 영어 그대로 사용합니다.

### 대화형 메뉴 열기

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Win11Debloat.ps1 -Language ko-KR -CLI
```

기본 모드, 앱 제거 모드, 마지막 설정 사용 등을 선택합니다. 앱을 직접 선택하는 과정에서는 GUI 창이 열릴 수 있습니다.

### 적용 예정 작업 먼저 보기

다음 명령은 **알려진 파일 형식의 확장명 표시** 옵션을 `-WhatIf`로 점검합니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Win11Debloat.ps1 -Language ko-KR -CLI -ShowKnownFileExt -WhatIf -SkipExplorerRestart
```

`-WhatIf`는 변경 처리의 모의 실행용입니다. 로그·설정 파일 처리 등 프로그램의 모든 동작이 사라지는 완전한 격리 실행을 뜻하지 않습니다. 실제 결과 확인과 복구 검증은 테스트 환경에서 별도로 수행해야 합니다.

### 검토한 설정 한 가지 적용

**다음 명령은 실제로 설정을 변경합니다.** 위 목록과 영향을 확인한 뒤 필요한 경우에만 실행하세요.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Win11Debloat.ps1 -Language ko-KR -CLI -ShowKnownFileExt -CreateRestorePoint -SkipExplorerRestart
```

파일 탐색기 자동 재시작을 건너뛰었으므로 필요하면 직접 PC를 다시 시작합니다. 복원 지점과 레지스트리 백업의 성공 여부를 확인하세요.

| 매개변수 | 의미와 주의점 |
|---|---|
| `-Language ko-KR` | 이번 실행의 표시 언어 지정 |
| `-CLI` | 대화형 명령행 메뉴 사용 |
| `-WhatIf` | 지원되는 변경 경로를 모의 실행 |
| `-CreateRestorePoint` | 변경 전에 시스템 복원 지점 생성 시도. 생성 보장 아님 |
| `-SkipExplorerRestart` | 파일 탐색기 자동 재시작 생략. 적용을 위한 수동 재시작이 필요할 수 있음 |
| `-LogPath 'C:\ExistingLogs'` | 기존 로그 폴더 지정. 폴더가 없으면 기본 로그 경로 사용 |
| `-Config 'C:\Settings\reviewed.json'` | 검토한 설정 파일 불러오기. 적용 목록을 확인 |
| `-RunSavedSettings` | 마지막 저장한 설정 재사용 |
| `-RunDefaults` | 원본 기본 설정과 기본 앱 제거 선택 적용 |
| `-RunDefaultsLite` | 기본 설정을 적용하되 기본 앱 제거는 제외 |
| `-AppRemovalTarget CurrentUser` | 앱 제거 대상 명시. 생략 시 기본 범위는 모든 사용자 |
| `-User` / `-Sysprep` | 다른 사용자·Windows 기본 사용자 대상으로 적용하는 고급 배포 기능 |
| `-Silent` | 사용자 확인을 생략. 복원 지점 생성 실패 뒤에도 계속할 수 있으므로 사전 검증한 자동화 전용 |
| `-SkipRegistryBackup` | 레지스트리 백업 생략. 복구 수단을 줄이므로 일반 사용자에게 권장하지 않음 |

`-User`·`-Sysprep`·SYSTEM 계정 실행은 사용자 프로필·앱 제거 범위·레지스트리 하이브를 함께 다루는 고급 기능입니다. Windows 10의 Sysprep 모드는 현재 진입 코드에서 차단됩니다. 운영 장비에서 처음 시험하지 마세요. 현재 전체 매개변수는 [Win11Debloat.ps1](../../Win11Debloat.ps1)의 `param` 선언이 기준입니다.

## 8. 백업과 복구

### 백업 종류를 구분하세요

| 종류 | 보존하는 것 | 보존하지 않는 것 |
|---|---|---|
| 설정 내보내기 | 선택한 앱·옵션·배포 설정 | 기존 Windows 상태 |
| 레지스트리 백업 | 선택한 레지스트리 변경과 관련된 이전 상태 | 삭제한 앱 전체·사용자 데이터·디스크 전체 |
| 시작 메뉴 백업 | 해당 사용자의 고정된 앱 배치 파일 | 앱 설치 파일·앱 데이터 |
| 시스템 복원 지점 | Windows가 관리하는 시스템 복원 정보 | 모든 개인 파일과 모든 삭제 앱의 복구 보장 |

레지스트리 백업은 관련 변경이 있을 때 생성됩니다. 앱 제거만 수행하는 경우 등에는 레지스트리 백업이 생성되지 않을 수 있습니다. 백업 생성에 실패하면 해당 변경 처리 전에 오류가 발생합니다. `-SkipRegistryBackup`으로 백업을 끈 경우에는 이 복구 수단이 없습니다.

시스템 복원 지점은 선택해야 시도합니다. 최근 24시간 이내 복원 지점이 있으면 새로 만들지 않을 수 있고, 시스템 보호 활성화나 생성에 실패할 수도 있습니다. 실패 안내를 무시한 채 진행하면 새 복원 지점이 없는 상태로 변경될 수 있습니다.

### 레지스트리 백업 복원

1. 실행 당시의 백업 파일과 로그를 보관합니다.
2. 같은 PC·적절한 대상 사용자에서 한국어판 GUI를 실행합니다.
3. **백업 복원 → 레지스트리 백업**을 선택합니다.
4. 백업 파일을 고르고 생성 시각·대상·변경 목록·복원할 수 없는 항목을 확인합니다.
5. 검증 오류가 있으면 파일을 임의로 수정하거나 검증을 우회하지 마세요. 정상적인 원본 백업을 사용합니다.
6. 복원을 실행한 뒤 성공·부분 실패·오류 안내와 로그를 확인합니다. 필요하면 파일 탐색기 또는 PC를 다시 시작합니다.

일부 기능은 레지스트리 백업으로 원복되지 않습니다. 복원 화면의 안내가 기준입니다. 출처를 알 수 없거나 수정된 백업은 적용하지 마세요. 실행 명령 등이 포함된 값은 추가 확인이 나타날 수 있습니다.

### 시작 메뉴 백업 복원

**백업 복원 → 시작 메뉴**에서 현재 사용자 또는 전체 사용자 범위를 확인합니다. 자동 백업 찾기 또는 백업 파일 직접 선택을 사용하고, 해당 사용자의 배치에 맞는 파일인지 확인한 뒤 복원합니다. 최초 변경 시 원래 `start2.bin`이 없으면 그 사용자에 대한 백업이 없을 수 있습니다.

### 앱을 다시 설치하려면

Microsoft Store나 해당 제작사의 공식 설치 경로에서 필요한 앱을 다시 설치합니다. 계정·라이선스·설치 가능 여부를 확인하세요. 모든 앱을 Store에서 다시 받을 수 있는 것은 아니며, 시스템 구성 요소·지원 중단 앱·Store 자체 제거는 복구가 더 어려울 수 있습니다. 레지스트리 백업 복원만으로 삭제 앱이 돌아오지는 않습니다.

### 시스템 복원을 사용하려면

Windows의 시스템 복원에서 실행 전에 생성된 복원 지점이 있는지 확인하고 해당 Windows 절차에 따라 진행합니다. 시스템 복원은 Win11Debloat의 레지스트리 백업 복원과 별도 기능입니다. 복구 여부를 확인하기 전 기존 백업을 삭제하지 마세요.

## 9. 로그·설정·백업 위치

일반 실행에서는 **프로그램을 실행한 계정**의 다음 경로를 사용합니다.

| 파일·폴더 | 역할 |
|---|---|
| `%LOCALAPPDATA%\Win11Debloat\Preferences.json` | 저장한 테마와 언어 |
| `%LOCALAPPDATA%\Win11Debloat\LastUsedSettings.json` | 마지막 선택 |
| `%LOCALAPPDATA%\Win11Debloat\Backups` | `Win11Debloat-RegistryBackup-*.json` |
| `%LOCALAPPDATA%\Win11Debloat\Logs\Win11Debloat.log` | 메인 실행 로그 |
| `%LOCALAPPDATA%\Win11Debloat\Logs\Win11Debloat-Run.log` | `Run.bat` 실행 로그 |

시작 메뉴 백업은 각 사용자의 아래 폴더에 별도로 저장됩니다.

```text
%LOCALAPPDATA%\Packages\Microsoft.Windows.StartMenuExperienceHost_cw5n1h2txyewy\LocalState
```

파일명은 `Win11Debloat-StartBackup-*.bak`입니다. 복원 과정에서 현재 배치도 `Win11Debloat-StartRestore-*.bak`로 보관할 수 있습니다.

`LOCALAPPDATA`가 없는 특수 배포 환경에서는 메인 스크립트가 실행 폴더를 데이터 기준 위치로 사용합니다. `-LogPath`로 기존 폴더를 지정하면 메인 로그 위치가 달라집니다. 다른 계정으로 관리자 권한을 얻었거나 다른 사용자에게 적용한 경우, **실행 계정의 데이터 경로**와 **대상 사용자의 시작 메뉴 경로**를 구분하세요.

## 10. 알려진 제한과 FAQ

### PowerShell 7에서 실행이 멈춥니다

현재 제품은 Windows PowerShell 5.1을 필요로 합니다. `powershell.exe`로 다시 실행하세요. PowerShell 7에 대한 자동 테스트 결과가 있어도 제품 전체의 지원을 뜻하지 않습니다.

### 한국어 Windows인데 영어로 표시됩니다

저장한 영어 설정이 Windows 표시 언어보다 우선합니다. `-Language ko-KR`로 실행하거나 GUI에서 한국어를 저장하세요. 언어 파일이 누락되거나 손상되었으면 같은 버전의 전체 파일을 다시 받습니다.

### Run.bat 창이 닫히거나 아무 창도 열리지 않습니다

`Win11Debloat-Run.log`를 확인하고, 관리자 권한 Windows PowerShell에서 [직접 실행 명령](#windows-powershell로-직접-실행)을 사용하여 오류를 확인하세요. UAC 취소, 불완전한 압축 해제, 실행 정책 제한, 파일 경로 문제를 구분합니다.

### 기본 모드를 누르면 무엇이 바뀌나요?

기본 모드는 원본의 추천 설정과 앱 제거 선택 흐름을 사용합니다. 설정은 버전에 따라 달라질 수 있습니다. 적용 전에 목록을 검토하세요. `-RunDefaults`와 `-RunDefaultsLite`는 앱 제거 포함 여부가 다릅니다.

### 옵션 체크를 해제하면 원래 상태로 돌아오나요?

선택 해제와 복원은 같은 뜻이 아닙니다. GUI의 적용 상태 감지·되돌리기 지원 항목을 확인하거나 해당 레지스트리·시작 메뉴 백업을 복원하세요. 일부 변경은 별도 복구 절차가 필요합니다.

### 적용 중 취소하면 이미 바뀐 것도 모두 복구되나요?

아닙니다. 취소는 남은 작업을 중단하는 동작입니다. 이미 적용한 변경은 자동으로 모두 롤백되지 않으므로 적용 내역·로그·백업을 확인하세요.

### 완료되었다고 나오는데 앱이 남아 있습니다

앱 제거 실패, 제거 결과 확인 불가, 다음 로그인 이후 처리 등이 서로 다릅니다. 완료 화면과 로그에서 해당 앱 ID의 결과를 확인하세요. 재부팅 전에 무조건 같은 제거를 반복하지 마세요.

### 파일 탐색기가 재시작되며 화면이 깜박입니다

선택한 옵션을 반영하기 위한 정상 경로일 수 있습니다. `-SkipExplorerRestart` 또는 GUI의 해당 옵션으로 건너뛸 수 있지만, 나중에 PC를 다시 시작해야 적용되는 설정이 있습니다. 작업을 저장한 상태에서 진행하세요.

### 백업이 있는데도 삭제한 앱이 돌아오지 않습니다

레지스트리 백업은 앱 설치 백업이 아닙니다. [앱 재설치 안내](#앱을-다시-설치하려면)를 확인하세요. 모든 기능의 완전한 원상 복구를 보장하지 않습니다.

### 업데이트 후 옵션이 다시 켜지거나 앱이 돌아왔습니다

Windows 빌드·정책·장치 보조 앱 설치 등의 변화일 수 있습니다. 현재 빌드에서 지원되는 옵션인지 먼저 확인하고, 기존 상태를 기록한 뒤 필요한 설정만 검토하여 다시 적용하세요.

### 버그나 번역 문제는 어디에 보내나요?

[한국어판 Issues](https://github.com/webiscorp/Win11Debloat-koKR/issues)에 아래 정보를 포함하여 등록하세요. 한국어판 번역·배포 문제와 원본 기능에서 재현되는 문제를 구분하면 원인 확인에 도움이 됩니다.

- 한국어판 커밋 또는 배포 버전
- Windows 버전·빌드와 표시 언어
- `$PSVersionTable.PSVersion` 및 관리자 권한 여부
- 실행한 명령·선택한 옵션·대상 사용자 범위
- 재현 단계, 기대 결과와 실제 결과
- 오류 문구·화면·관련 로그(공개 전 계정명·개인 경로 등 가림)

## 11. 원본 업데이트와 한국어판 업데이트

WEBIS는 원본의 변경을 확인하고 추가·변경된 문자열, 기능 ID, 매개변수, 설정·백업 형식, 테스트와 다운로드 경로를 함께 검토합니다. 원본 변경 감지와 한국어판 Release는 별도 단계이며 **무검증 자동 배포를 하지 않습니다**.

새 버전은 변경 내역을 읽고, 기존 `Preferences.json`·`LastUsedSettings.json`·로그·백업을 보관한 뒤 테스트 환경에서 먼저 확인하세요. 원본 파일을 덮어쓰거나 두 버전을 혼합하면 한국어판 수정 사항이 사라질 수 있습니다. 자세한 절차는 [유지보수 문서](MAINTENANCE.ko-KR.md)를 참고하세요.
